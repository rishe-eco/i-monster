## Built

- **The editor** (`admin/editor.tsx`, `admin/editor-model.ts`), ProseMirror with the six packages of plan §6.6 and nothing else. It sits behind one component (`value`, `onChange`, `lang`, `readOnly`), so PD-7's textarea fallback could replace it without touching anything else.
  - **The schema** mirrors `shared/doc.ts` and imports its rules (`isAllowedHref`, `stripXmlForbidden`, `normalizeDoc`, `validateDoc`). Its parse rules exist only for `<p>`, `<mark>` and an `<a>` with an allowed address. So pasted `<b>`, `<strong>` and `<em>` are plain text, and a `javascript:` link is its text. Pasting strips the XML-forbidden characters (S-5). Every body sent has been through `normalizeDoc` (S-4).
  - **Bidi** is drawn as `Decoration.inline(…, { nodeName: 'bdi', dir, lang })` from `lib/bidi.ts`'s runs, so there's no `style` attribute (the CSP). It isn't drawn while a keyboard is composing, and comes back 60 ms after `compositionend`.
  - **The toolbar:** Link (opens "Link address" in place, with Done and, for an existing link, Remove link; an address `isAllowedHref` refuses is refused at the field) and Highlight. The tools and actions sit in a sticky **dock** at the foot of the editor, so they stay in reach with the keyboard up. The dock's height sets ProseMirror's scroll margins.
  - **The placeholder** is CSS `::before` on a class (AC-18). The title is a real `<label>` "Title (optional)". The body is labelled "Entry text" (visually hidden).
- **The slot** (`admin/composer.tsx`): `NewEntry` is always shown when nothing is being edited (W1). The language control comes first and starts at `GET settings`' `lastLanguage` (PD-10). It is fixed once a row exists. Edit puts the entry in the same editor, inside B5's frame and header lines, which moved from `entries.tsx`. `DocView` is gone; `Runs` stays.
- **Requests** (`admin/writes.ts`, PD-11): new text is `POST entries` with a `publishKey` made at the first keystroke. After that, work is by id: Save is `PUT`, and publishing a draft is `PUT` then `POST …/publish`. A retry whose text changed after a lost answer follows the existing row with a `PUT` (and a publish).
- **Nothing lost** (`admin/buffers.ts`, pure, storage injected; `admin/browser-storage.ts`, the one file that names `localStorage`):
  - three buffers per kind (`imnstr:entry:unsent|edit|kept`), each written on every change and cleared only after the server confirms, or after a second Discard;
  - "Kept on this phone" is the only draft signal, and it is hidden when the browser refuses to store;
  - AC-43's keep and offer-back (kept text is a stack);
  - a closed tab's text is offered back on opening ("You left something here."), and so is an edit's ("You left changes here.");
  - failures just above the actions (W5), and only a tap retries;
  - a 401 doesn't unmount the editor: `api()` takes `{ keepOnSignedOut }`, used only by the editor's writes. **Sign in and publish** (or "and save", "and unpublish") runs `signIn()` and then reruns the action once. The new `SessionInfo` goes up to `Home`.
- **Confirmations:** "Published. It's out there." with the address, Open and Copy link ("Copied" for `limits.copiedMs`); "Saved. …"; "Draft saved. …", with the button then reading "Saved". The editor empties only after the server confirms a publish.
- **Tests:** `tests/e2e/editor.spec.ts` (42 tests × 2 schemes after the review), `tests/unit/buffers.test.ts`, `tests/unit/editor-model.test.ts`, `tests/unit/request-size.test.ts` (S-9).

**The review changed** (this commit):
1. **A language switch after a lost answer could publish the same text twice.** The lane made a new publish key when the language changed after a send that got no answer, because the server answers a known key with the row in the language first sent. But if that send had landed (a publish whose answer was lost), the retry under the new key made a second entry. The first one was already live, while the screen said "Not published yet." Now the key is never replaced. The language control is fixed while a send is unanswered (`NETWORK` or `UNEXPECTED`, no row known), until an answer comes. Emptying the text doesn't drop the key then either. The price: text sent offline in the wrong language keeps that language, unless it is discarded.
2. **Leave over unsaved changes lost the "Back to your unsent entry." notice.** The leave dialog ended the edit itself (`edit-cancelled`), and then Cancel ended it again. The second call found the kept text already restored, so it said nothing, and the notice's Discard was missing too. Now Leave drops only the changes, and Cancel or the next Edit does the rest.
3. **At 180 px, Highlight ran 22 px into the page's gutter**, in the new-entry editor and in the frame. The tools group didn't wrap. There was no sideways scroll, so the lane's test (which only checked the screen edge) passed. Now the group wraps, and the test checks every control against the column (the `main` content box), in the new editor and in the frame with a Persian entry.

Each fix has a test that fails on the lane's code and passes now.

## Decided

The lane's calls (report item 4), accepted at review:

- **The unsent buffer carries the row's `id`,** and kept text is a stack. A page that opens with unsent text sets it aside (kept) at once. Put it back swaps it with whatever has been typed since.
- **The edit buffer** is written only while the text differs from the entry.
- **The wording for an edit buffer found at open:** "You left changes here. Edits to an entry, from earlier on this phone. They aren't saved, and the entry hasn't changed." It offers Put them back and Discard, and Discard asks once more.
- **"Leave without saving?"** before Cancel, or Edit on another row, with unsaved changes. This goes beyond the card, but it follows AC-43's intent: one stray tap shouldn't throw an edit away.
- **Save or Publish in an edit with text kept closes the frame** and says what it did above the returned text.
- **A failure stays until a write succeeds.** Only refusals about the text clear when the person types. `BODY_REQUIRED` is checked in the browser first.
- **Save and Save draft have no "Saving…" label** (W7). They only disable. Publish says "Publishing…" (plate 7).
- **The storage-refused variant** of the failure copy, and "Kept on this phone" hidden then.
- **The toolbar is a labelled group,** not `role="toolbar"`, which would promise arrow-key movement.
- **Title:** control and XML-forbidden characters are dropped as they arrive.
- **A draft's header** stays "Draft". Plate 12's "saved from phone" would need to know the device.

**Where the plan or card was wrong** (report item 5, answered here):
1. **`localStorage` was banned outright** by `house-rules.test.ts` and `assets.test.ts` (B4b), which PD-12's buffers contradict. **Accepted as a rule change:** it may be named only in `admin/browser-storage.ts`. A test pins the three key shapes, and that neither file mentions a session, token, csrf or cookie. The bundle still may not name `sessionStorage`, `document.cookie` or `indexedDB`. AC-10's "no tokens in local storage" still holds, by the same test.
2. **`admin-copy.test.ts` banned the word "left"**, which plate 9's "You left something here." uses. It is narrowed to a digit-led count. **Accepted.**
3. **ProseMirror's stylesheet** breaks the admin CSS rules (`#8cf`, `px`, `left`/`right`). It is rewritten with tokens and logical properties, and the unreachable rules are left out. **Accepted.** Its `font-feature-settings: 'liga' 0` was checked in Persian: lam-alef still joins (it is a required ligature in Vazirmatn), as seen by the reviewer at 360 px.
4. **Plan §5 B6 says a 401 opens the re-authentication dialog.** The card says `signIn()`, and the card is right (re-authentication needs a live session). For the plan's changelog.
5. **The plan says "View"; the plates say Open.** Open is used. For the plan's changelog.
6. **"After an hour idle" in plate 9's signed-out copy** wasn't true for every way a session ends (24 h absolute, or a passkey removed elsewhere), and a 401 doesn't say which. **The founder's call (F-16): do what makes sense.** It now says "You were signed out. Sign in to finish. Your text stays right here." (`admin/copy.ts`).
7. **The title had no length limit** (`readTitle`); only Nginx's `1m` stopped a huge one. **The founder's call (F-16): a large cap.** `limits.titleMaxChars` is 1,000 UTF-16 code units, counted after trimming. Past it, the API answers `REQUEST_INVALID` (tested by the body's bytes), and the field's `maxlength` stops there, so the person never meets the refusal.
8. **`signedInAdmin` couldn't run twice** at once, and `globalSetup.ts` didn't watch `shared/`, `lib/bidi.ts` or `lib/i18n.ts`. Both are fixed.

**Seen at review, not changed:**
- **A saved draft stays in the unsent buffer** (with its id), so text can be edited further after Save draft. When the page opens again, it is offered as "Unsent text from earlier on this phone. It isn't published." That is true, but the text is also in Entries as a draft. Nothing is lost. Look at it with the phone check.
- **The leave dialog** also asks before Edit when an edit buffer is on offer and not chosen. Its words ("The changes to this entry…") fit an open edit better than an offer.
- **The dock grows with a failure notice in it** (about 250 px with the toolbar and actions). At 360 × 400 the line being typed stays above it (tested), but little text shows. Judge it on the phone.
