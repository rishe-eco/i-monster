## Built

- **Image.** `Dockerfile`: `node:24-slim`, one stage, `npm ci --omit=dev --ignore-scripts`; better-sqlite3 loads its prebuilt glibc `linux-x64.node`, so no toolchain and no build stage. Runs as `node` (uid 1000), `NODE_ENV=production`, `node --import tsx server.ts`, healthcheck by `fetch` on `/healthz`. `tsx` moved to `dependencies`. `.dockerignore` keeps the host's `node_modules`, `.git`, `.claude`, `.env*`, data and test output out.
- **Compose.** `docker-compose.prod.yml`: project `imnstr`, `127.0.0.1:4100:4100`, `/srv/imnstr/data:/data` and `/srv/imnstr/backups:/backups`, `restart: unless-stopped`, `mem_limit: 256m`, json-file logs 10m × 3 (the plan's "log retention"), `env_file: .env`. `data/` and `backups/` gitignored.
- **Nginx.** `deploy/nginx/imnstr.conf`: 80 → 443, `www` → apex, `proxy_pass http://127.0.0.1:4100` with `Host` and `X-Forwarded-Proto`, `access_log off`, error log at `crit`, zone `imnstr_auth` on `/admin/api/auth/`, TLS session cache `imnstr_tls`, no `add_header`, no `default_server`, IPv4 and IPv6. `imnstr.bootstrap.conf`: port 80 only, for the first certificate.
- **Backups.** `scripts/backup.ts` (`npm run backup`): `db.backup()` to a new file, switched to a rollback journal, `integrity_check` on the copy, exit 1 on failure; refuses an existing destination. `deploy/backup.sh`: runs it in the container, keeps 14 days, `rsync -e ssh` to `$BACKUP_REMOTE`, exits 1 with a message when that is unset.
- **`deploy/README.md`**: first-time setup, routine deploys, checks, CLIs, backups and cron, restore into a scratch container.
- **Tests.** Unit `deploy.test.ts` reads the confs, Dockerfile, `package.json` and `.dockerignore` as text. Integration `backup.test.ts`: same rows, `integrity_check` ok, one self-contained file, refusals.

**The review changed** (`ed83c99`, and the README with this record):
- **Every backup left `-wal` and `-shm` files beside it.** The copy inherits WAL mode from the live file, and the read-only check couldn't clean up after itself. The prune deletes only `imnstr-*.db`, so the sidecars would have piled up forever. Found by running the image. The copy is now switched to `journal_mode = DELETE` before the check, and the test asserts no sidecars.
- **`http2` dropped from the 443 listens.** In nginx 1.18 that flag belongs to the address and port, not the server block. It would have switched HTTP/2 on for every tenant sharing `:443`, and root-app listens without it. Checked on the box: no other site enables it.
- **The live conf is a copy in `sites-available`, not a symlink into the repo** (plan §7, config §7; accepted by the founder). certbot's nginx plugin edits the live file for a moment at each renewal, which must not happen in the git checkout. And a `git pull` must not change what another tenant's reload loads unchecked. Conf changes keep the previous file to roll back to.
- **`certbot certonly … --deploy-hook 'nginx -t && systemctl reload nginx'`,** so a renewed certificate is actually loaded.
- **The README's commands work for a sudo user** (found by the founder at the first deploy). Every command is prefixed `sudo`, and files root owns are written through `sudo tee`, since `sudo cmd > /etc/file` fails. One command per line, so each can be pasted alone.
- **The restore checks `/log`,** not `/log/`, which is a 404.

## Decided

The lane's calls (report item 4), each accepted at review:

- **No build stage:** the prebuilt binary, confirmed by building the image.
- **The certificate by `certonly --nginx` with a bootstrap conf,** in place of the plan's `certbot --nginx`. certbot never edits the repo's conf, so there is nothing to sync back (the plan's trap and checklist §6's "certbot's edits" item no longer apply).
- **Zone `imnstr_auth:1m rate=30r/m`, `burst=10 nodelay`, 429 on refusal.** B4a may tune it.
- **`client_max_body_size 1m`.** B5 and B7 may raise it.
- **`backup.ts` opens the live file through `openDb`,** so it also sets `busy_timeout` and would run any pending migration. Harmless, because the app migrates at boot first.
- **`backup.sh` makes the local copy before failing on a missing `BACKUP_REMOTE`.** The founder deferred the off-box target, and the cron line is installed without it until then.
- **The unit test strips comment lines** before asserting, so comments may name `add_header` or `default_server`.
