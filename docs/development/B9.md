**The review changed** (this commit):
1. **A tap on the landing hero did nothing on an iPhone.** The lane read `pointerType` from the `click` event. Safari before 18.2 gives a click no `pointerType`, and 18.2 on reports a tap's click as `"mouse"` (WebKit bug 282988), so the reveal never toggled there: no hover, no focus, nothing but the intro. Now the type comes from the link's `pointerdown`, cleared at each click, so a keyboard's Enter (no pointerdown) is never a tap. New test: a touch `pointerdown` followed by a plain `MouseEvent` click, then by a `PointerEvent` click typed `"mouse"`, each toggles; Enter after them doesn't. It fails on the lane's code and passes now. (Its first draft passed on the lane's code too, because the intro's own timers flipped the class while `toHaveClass` waited; the test now plays the intro out with `page.clock.runFor(3000)` first.)

## Decided

The lane's calls (report item 4), accepted at review:
- **The link's name is given by `aria-label`.** With only `aria-hidden` letters, Chromium names the link "i M NST R" (inline-blocks are spaced in name computation). The label equals the visible resting text, so label-in-name (WCAG 2.5.3) holds.
- **Header wordmark 22/26 px, eyes 17/20, phone nav gap 8 px.** The design's own range. Revealed (keyboard focus), the nav takes a second row at 360; nothing scrolls.
- **The hero is fitted to its eyes,** not to `19vw`. At 180 px it is 17 px (the old cap gave 34, which overflowed when revealed: 5.5 × 34 = 187 px against a 136 px column). Seen at review in Edge: small but whole. At 180 px with 200% text together it falls to about 2 px; that pair is outside the card's matrix. For step 9's design review.
- **A mouse click or Enter on the hero does nothing** (`preventDefault`): hover and focus already reveal, and the link is the page you're on.
- **Container queries in rem, against `CLAUDE.md`'s "breakpoints are in em".** The rule exists so breakpoints follow the reader's text size. In a container query, rem is the root's own computed size (and em would be the container's, here the body's 17 px reading size, which makes the number meaningless), so `17rem` follows text size as the rule intends. Proposed for the founder: "Media-query breakpoints are in `em`; container queries in `rem`." (open-work F-19.)
- **Eyes' white and pupil stay the same in dark** (the export does so); forced colours draw them in system colours.
- **The entry page's date counts as a 24 px date link** (design README "inline date links get 24px").
- **The podcast empty state's eyes are above the line,** as the card says; plate 4 draws them beside it. One class change if the founder prefers the plate.
- **The draw-in on the podcast lede is ready but idle:** the lede has no `<mark>` until F-2 brings its phrase. A test places one to prove the rule.
