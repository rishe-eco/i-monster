The server writes the new list into the other half of the position space (bands 0 and 1000), then deletes the old rows, so `episode_last_link` never fires on a save. **The review changed** (this commit):
1. **Clearing the date in an edit showed today, while Save kept the episode's own date.** The field's fallback for an unchosen date is the server's today, which is right for a new episode (the server fills today) but wrong for an edit (an edit without a date keeps the episode's). So an episode dated 3 Oct showed 10 Oct after its date was cleared, Save kept 3 Oct, and the change also counted as unsaved. Now a cleared date in an edit becomes the episode's own date again, so the screen shows what a save keeps and nothing is unsaved. The test fails on the lane's code ("Received: 2026-10-10") and passes now.

## Decided

The lane's calls (report item 4), accepted at review:
- **The new-episode form closes after Save draft** (entries keep their editor open). A saved draft is on the server; a form that kept its key and row would reopen as "New episode" holding an old draft. The draft is one Edit away.
- **More than two tags is `TAGS_ONE_OR_TWO` on any save** (two columns, nowhere for a third). Tag cap 100.
- **A label with no address is `LINK_NOT_HTTPS`;** an address with no label is `REQUEST_INVALID` (the form refuses it at the label first). An empty row is dropped.
- **On `PUT`, an empty date keeps the episode's own** (and now the form shows that, fix 1). On `POST` an absent date is today, and the form's buffer keeps `''` until a day is picked, so text kept overnight isn't pinned to yesterday.
- **Link positions in two bands** (0 and 1000), so a save never collides and positions don't grow.
- **The section opens itself** when the page opens with text to offer back, so an offer is never hidden.
- **The confirmation words** where the plates have none: "Published. It's on the podcast page." (with the address, Open and Copy link); "Draft saved. It's in Podcast, not on the site. …"; "Unpublished. It's in your podcast list as a draft."; "Publishing puts it back at <date>, its date. …" before a republish. Plate 11's "Saved. The episode keeps its date and its place." and plate 12's "Published, at 3 Oct 2026." as drawn.
- **`NAME_REQUIRED` and `REQUEST_INVALID` have episode wording** in the failure notice, since the shared messages are about passkeys.
- **The show links are `big-row` rows** at title size, and the intro is a locale string (`podcast.lede`), not content. Plate 4's desktop "Listen wherever you like" block and "New episodes land on YouTube first." aren't built, as the card said.

The edits are right: each now asserts the new truth, and `record.test.ts` gains S-18's test. A card should list such tests (the lane's item 7).
